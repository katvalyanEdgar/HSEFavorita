# hw3: прогнозирование продаж favorita с экзогенными признаками

## 1. постановка задачи и гипотеза

цель работы - построить воспроизводимый пайплайн прогнозирования дневных продаж `unit_sales` для пар `store_nbr` / `item_nbr` на 16 дней вперед на данных favorita.

гипотеза: качество прогноза должно улучшаться при переходе от простых инерционных бейзлайнов к глобальной ml-модели с лагами и экзогенными признаками. нейросетевая модель проверяется как более гибкий нелинейный вариант, способный использовать те же признаки и категориальные embeddings.

## 2. описание данных

используются файлы:

- `train.csv`: дата, магазин, товар, продажи, промо-флаг;
- `test.csv`: будущий 16-дневный горизонт kaggle;
- `items.csv`: семейство товара, класс, флаг скоропортящегося товара;
- `stores.csv`: город, штат, тип магазина, кластер;
- `oil.csv`: цена нефти как внешний макроэкономический признак;
- `holidays_events.csv`: праздники и события;
- `transactions.csv`: доступен, но не используется как будущий экзогенный признак, потому что для test-периода будущие транзакции неизвестны.

отрицательные значения `unit_sales` интерпретируются как возвраты и клипуются в 0 перед лог-преобразованием и расчетом метрик.

## 3. методология эксперимента

валидация имитирует kaggle-прогноз: последний блок длиной 16 дней откладывается как holdout, предыдущие даты используются как история. основная метрика - `NWRMSLE`:

```text
sqrt(sum(w_i * (log(1 + y_pred_i) - log(1 + y_i))^2) / sum(w_i))
```

вес `w_i = 1.25` для `perishable = 1`, иначе `w_i = 1.0`.

дополнительно считаются `RMSLE`, `MAE`, `RMSE` и `WMAPE`. они нужны для интерпретации ошибок: `RMSLE` и `NWRMSLE` ближе к kaggle, `MAE` и `RMSE` показывают абсолютный масштаб ошибки, `WMAPE` нормирует ошибку на объем продаж.

все метрики считаются после восстановления прогноза в исходную шкалу продаж.

## 4. признаки

сгенерированы группы признаков:

- календарные: день недели, месяц, неделя, выходной, начало/конец месяца, payday;
- лаговые: `lag_16`, `lag_17`, `lag_18`, `lag_21`, `lag_28`, `lag_35`, `lag_42`, `lag_56`, `lag_91`, `lag_182`, `lag_364`;
- rolling means с безопасным сдвигом на 16 дней;
- промо: `onpromotion`;
- внешние признаки: цена нефти, праздники, события, город/штат/тип/кластер магазина, семейство/класс/скоропортимость товара.

лаги меньше 16 дней не используются, чтобы не подмешивать фактические продажи из validation/test горизонта.

## 5. модели

бейзлайны:

- naive: повторяет последнее известное значение ряда;
- seasonal naive: повторяет недельный сезонный паттерн последних 7 дней;
- auto theta: классическая per-series модель из `statsforecast`;
- auto ets: экспоненциальное сглаживание из `statsforecast`.

основные модели:

- catboost: глобальная ml-модель на лог-таргете `log1p(unit_sales)`, использует категориальные и числовые признаки;
- torch mlp: нейросетевая табличная модель с embeddings для категориальных признаков и mlp-блоком для нелинейных взаимодействий.
